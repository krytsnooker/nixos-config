04 Installation

Prerequisites Boot the BC-250 from a NixOS minimal installer USB before running any of these commands.

1a Verify the NVMe is visible

Confirm /dev/nvme0n1 appears and shows ~500 GB. If the device name differs, update disko/bc250.nix before proceeding.

lsblk

1b Connect to the internet

The Realtek RTL8111H NIC should be detected automatically. Check the interface name first:

ip link

If the interface is not already up, bring it up manually (replace enp1s0 with the name shown by ip link):

sudo ip link set enp1s0 up
sudo dhclient enp1s0
ping -c 3 1.1.1.1

1c Get the config onto the machine

Install git into the live environment:

nix-shell -p git

The repo is private — copy your SSH key from the homeserver. Run this on the homeserver:

scp ~/.ssh/id_ed25519 ~/.ssh/id_ed25519.pub nixos@<bc250-ip>:/home/nixos/.ssh/

Then on the BC-250 installer, set permissions and verify the key works:

chmod 600 ~/.ssh/id_ed25519
chmod 644 ~/.ssh/id_ed25519.pub
ssh -T git@github.com
# Expected: Hi krytsnooker! You've successfully authenticated...

Clone the config repo:

sudo mkdir -p /mnt/etc/nixos
git clone git@github.com:krytsnooker/bc250-nixos-config.git /tmp/nixos-config
sudo cp -r /tmp/nixos-config/. /mnt/etc/nixos/
Expected state The disk is not yet partitioned at this point — /mnt is a tmpfs in the live environment. Disko in the next step creates and mounts the real partitions at /mnt.

1d Run disko — automatic partitioning, formatting, and mounting

This single command replaces all manual fdisk, mkfs, and mount steps. It reads disko/bc250.nix and sets up the disk exactly as declared:

sudo nix run github:nix-community/disko -- \
  --mode disko \
  /mnt/etc/nixos/disko/bc250.nix
Destructive This erases all data on /dev/nvme0n1. The disk is left mounted at /mnt ready for install.

1e Verify mounts

lsblk
mount | grep /mnt

# Expected from lsblk:
  nvme0n1p1   512M   /mnt/boot
  nvme0n1p2     8G   [SWAP]
  nvme0n1p3  ~491G   /mnt

1f Generate hardware configuration

Output goes directly into the config repo. Review the generated file — check that the NVMe UUID and filesystem types look correct:

sudo nixos-generate-config --root /mnt --dir /mnt/etc/nixos/hosts/bc250
cat /mnt/etc/nixos/hosts/bc250/hardware-configuration.nix

Commit this file — it is machine-specific and should never need to be regenerated unless hardware changes:

cd /mnt/etc/nixos
sudo git add hosts/bc250/hardware-configuration.nix
sudo git commit -m "bc250: add hardware configuration"

1g Install NixOS

This step downloads and builds the entire system closure. Set a root password when prompted:

sudo nixos-install --flake /mnt/etc/nixos#bc250

1h Reboot

Remove the USB drive when the machine powers down:

sudo reboot

05 Package hashes

Context All config files are already in the repo. The 4 custom packages have lib.fakeHash placeholders that must be replaced with real hashes before they build. This is a standard NixOS workflow — each package errors once with the correct hash.

What needs fixing

FileHashes needed
pkgs/cyan-skillfish-governor.nixhash (source) + cargoHash (Rust deps)
pkgs/bc250-acpi-fix.nixhash (source)
pkgs/bc250-cpu-oc.nixhash (source)
pkgs/citron-neo.nixhash (AppImage download)

The process — repeat until clean

Run the rebuild. It will fail on the first package with a hash mismatch error:

sudo nixos-rebuild switch --flake /etc/nixos#bc250

The error will show the correct hash:

error: hash mismatch in fixed-output derivation:
       specified: sha256-AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA=
          got:    sha256-ABC123realHashHere...=

Copy the got: hash and replace lib.fakeHash in the relevant file, then commit and rebuild:

nano /etc/nixos/pkgs/<relevant-file>.nix   # replace lib.fakeHash
cd /etc/nixos
sudo git add pkgs/
sudo git commit -m "bc250: fix package hashes"
sudo nixos-rebuild switch --flake /etc/nixos#bc250
Iterations Typically 5–6 rounds — cyan-skillfish-governor needs 2 hashes (source + Rust deps), the others need 1 each. Repeat until nixos-rebuild switch completes without error.

Push the fixed hashes back to GitHub:

cd /etc/nixos
git push

Verify hardware unlock

After a successful rebuild, verify all three hardware unlock services are active.

GPU Governor

Caution Never set minimum GPU voltage below 700 mV — this locks the GPU to 1500 MHz permanently until reboot. 
systemctl status cyan-skillfish-governor
cat /sys/class/drm/card0/device/pp_dpm_sclk

ACPI Fix

Enables CPU P-states (800 MHz → 3200 MHz) and C-states (idle power savings). Requires a reboot to take effect:

sudo reboot

After reboot, verify P-states and C-states are available:

ls /sys/devices/system/cpu/cpu0/cpuidle/
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_available_frequencies

CPU Overclock — 3900 MHz @ 1275 mV (+9% over stock)

systemctl status bc250-cpu-oc
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_cur_freq

Tag working state

Once gaming is confirmed working, tag the git state as a known-good baseline:

cd /etc/nixos
git tag working-$(date +%Y-%m-%d)
git push --tags

To roll back to a tag:

git checkout working-YYYY-MM-DD
sudo nixos-rebuild switch --flake /etc/nixos#bc250

To roll back at the bootloader level without git (selects previous NixOS generation):

sudo nixos-rebuild switch --rollback

07 Emulators module optional

Includes RetroArch (all cores), PCSX2 (PS2), Dolphin (GameCube/Wii), Citron-neo (Switch). All files are already in the repo — just toggle the line in flake.nix and rebuild.

Enable / disable

Remove the # from # ./modules/emulators.nix in flake.nix to enable; add it back to disable. Then rebuild:

sudo nixos-rebuild switch --flake /etc/nixos#bc250

BIOS and keys — staging directory

BIOS and key files are staged on the homeserver at //192.168.0.110/hsas01 → amdbc250/bios/. Drop your files into the correct folder:

Transfer to BC-250

Once the BC-250 is up and SSH is running, copy the staging directory from the homeserver. Run this on the homeserver:

scp -r /mnt/server-pc/amdbc250/bios/ kryt@<bc250-ip>:/etc/nixos/bios/

Then trigger a rebuild on the BC-250. The activation script copies everything to the correct emulator locations:

sudo nixos-rebuild switch --flake /etc/nixos#bc250
Safe to re-run Files are copied with cp -rn (no-clobber) — existing files are never overwritten. Emulator saves are safe. Re-running after adding more files only copies the new ones.

08 LLM module optional

Includes Ollama with ROCm backend configured for gfx1013, stopped by default. All files are already in the repo — just toggle the line in flake.nix and rebuild.

Before enabling Set BIOS memory split to 10 GB GPU / 6 GB CPU for maximum usable VRAM (~9–9.5 GB after driver overhead).

Enable / disable

Remove the # from # ./modules/llm.nix in flake.nix to enable; add it back to disable. Then rebuild:

sudo nixos-rebuild switch --flake /etc/nixos#bc250

Starting / stopping Ollama

sudo systemctl start ollama
sudo systemctl stop ollama
systemctl status ollama

Recommended models

ModelQuantVRAMEst. TPSUse case
Qwen2.5-Coder 7B InstructQ8_0~7.7 GB50–70 t/sDaily driver — fast, top-tier at this size
Qwen2.5-Coder 14B InstructQ4_K_M~9.0 GB35–48 t/sLarger context, stronger multi-file reasoning
DeepSeek-R1-Distill-Qwen 14BQ4_K_M~9.0 GB35–48 t/sComplex / algorithmic — chain-of-thought reasoning
Qwen2.5-Coder 14B InstructQ6_K~12.0 GB20–30 t/sHigher quality quant — requires CPU layer offload
 
# Pull daily driver
ollama pull qwen2.5-coder:7b-instruct-q8_0

# Pull secondary (larger context / complex problems)
ollama pull qwen2.5-coder:14b-instruct-q4_K_M

# Pull reasoning model
ollama pull deepseek-r1:14b-qwen-distill-q4_K_M
ROCm note gfx1013 is not a standard desktop ROCm target. If Ollama fails to use the GPU, test HSA_OVERRIDE_GFX_VERSION=11.0.0 first (RDNA2), then fall back to 10.3.0 (RDNA1).
