Hardware

Media and user data live on a Windows 10 machine at 192.168.0.110 with a SAS DAS attached via HBA, mounted over CIFS at /mnt/server-pc.

Swap: 4 GB swapfile at /swapfile.

CIFS mounts

Mount pointRemote sharePurpose
/mnt/server-pc//192.168.0.110/hsas01General DAS access — media, backups, music

CIFS ownership CIFS mounts don't support real UNIX ownership — it is set at mount time via uid=/gid=. The Nextcloud data mount uid= is derived from homeserver.nextcloudUid declared in modules/nextcloud.nix (default 991) — change that option and both the service UID and the mount option update together.

Flake rule Flakes only see git-tracked files. Stage every new file before rebuilding: git add <file>. Modifications to existing tracked files are picked up automatically.

Rebuilding

# Apply config and activate immediately
sudo nixos-rebuild switch --flake /etc/nixos#homeserver

# Test-activate without changing the boot default
sudo nixos-rebuild test --flake /etc/nixos#homeserver

# Stage for next boot only (current system unchanged)
sudo nixos-rebuild boot --flake /etc/nixos#homeserver

# Roll back to the previous generation
sudo nixos-rebuild switch --rollback

After adding/editing an app

Apps under apps/ are referenced by nix store path in ExecStart. A rebuild copies the source into the store and rewrites the service unit. After switch, no manual systemctl restart is needed — the unit already points at the new store path.

systemctl --failed                 # anything that didn't start
journalctl -u <service> -f        # live logs

Snapshots

Tag the repo whenever things are known-good:

git tag working-YYYY-MM-DD
git push --tags   # if you have a remote

To restore a snapshot:

git checkout working-YYYY-MM-DD
sudo nixos-rebuild switch --flake /etc/nixos#homeserver

Latest stable tag: working-2026-09-13

Secrets

Never stored in this repo. Copy machine-to-machine via scp or USB — never paste values into chat or logs.

Verify all secrets are present: bash /home/kryt/check-secrets.sh

/home/kryt/.smbcredentials chmod 600 · kryt:kryt

JSON format (despite the .php extension — nextcloud34 module requirement). The instanceid, passwordsalt, and secret values must match the backup exactly; changing them invalidates all user passwords.

{
  "instanceid":    "<from backup config.php>",
  "passwordsalt":  "<from backup config.php>",
  "secret":        "<from backup config.php>",
  "mail_smtppassword": "<gmail app password>"

/var/lib/mc-control/curseforge.env chmod 600 · mcctl:mcctl

Required for CurseForge plugin search in mc-control. Create at console.curseforge.com.

CURSEFORGE_API_KEY=<your api key>

Write safely (avoids shell expansion of $ in bcrypt keys):

sudo tee /var/lib/mc-control/curseforge.env <<'EOF'
CURSEFORGE_API_KEY=<your api key>
EOF
sudo chown mcctl:mcctl /var/lib/mc-control/curseforge.env
sudo chmod 600 /var/lib/mc-control/curseforge.env

SSL / external access

Let's Encrypt certificates managed by NixOS ACME (auto-renews). Ports 80 and 443 must be forwarded from the router to this machine.

  • intrentaka.com / www.intrentaka.com → Emby (localhost:8096)
  • cloud.intrentaka.com → Nextcloud

Certificate files are managed by the acme-intrentaka.com and acme-cloud.intrentaka.com systemd services. They live under /var/lib/acme/ and are renewed automatically. No manual action needed unless the domain or nginx config changes.

DNS requirement Both domains must resolve publicly to this machine's WAN IP before ACME can issue or renew. If the WAN IP changes, update the router port-forwarding and the DNS A records.

Router — TP-Link ER605

Port forwarding is under Transmission → NAT → Virtual Servers (standalone UI) or Settings → Transmission → NAT → Virtual Servers (Omada controller). Required rules:

InterfaceExternal portInternal IPInternal portProtocol
WAN80192.168.0.12080TCP
WAN443192.168.0.120443TCP
ER605 gotcha The ER605 does not support hairpin NAT (NAT loopback). LAN clients cannot reach intrentaka.com or cloud.intrentaka.com via the external IP — they need the Pi-hole local DNS overrides below. Port forwarding rules can also be lost after a firmware update or factory reset.

LAN access — Pi-hole split-horizon DNS

Pi-hole serves as the LAN DNS resolver (port 53). Local overrides at /var/lib/pihole/etc-pihole/custom.list make LAN clients resolve the external domains directly to the server's LAN IP, bypassing the router entirely:

192.168.0.120 intrentaka.com
192.168.0.120 www.intrentaka.com
192.168.0.120 cloud.intrentaka.com

This file lives in the Pi-hole container volume — it is not tracked in the NixOS config and must be recreated if /var/lib/pihole/ is wiped. After editing:

sudo systemctl restart podman-pihole.service

Fresh install

Reinstall vs new hardware On a reinstall of the same machine, skip nixos-generate-config. The partition UUIDs in hardware-configuration.nix are already in git. The partition script below recreates them exactly, so the existing config works without changes. Only regenerate if you swap hardware.

Step 1 — partition, format, mount

A ready-to-run script lives in the repo at scripts/partition-homeserver.sh. Boot the NixOS installer, then:

# Default: preserves existing partition UUIDs (no need to regenerate hardware config)
bash /path/to/scripts/partition-homeserver.sh /dev/nvme0n1

# New or different hardware: assign fresh UUIDs, then run nixos-generate-config
PRESERVE_UUIDS=no bash /path/to/scripts/partition-homeserver.sh /dev/nvme0n1

The script creates three partitions, formats them, mounts everything at /mnt, and creates the 4 GB swapfile. Sizes: ESP 512 MiB · root 60 GiB · home remainder (~190 GiB).

Step 2 — install

  1. Clone the config repo: git clone <url> /mnt/etc/nixos
  2. Create all secrets files listed in the Secrets section above.
  3. Run the installer: nixos-install --flake /mnt/etc/nixos#homeserver
  4. Reboot, then set the user password: passwd kryt
  5. Verify the CIFS mount: systemctl status 'mnt-server\x2dpc.mount'

Step 3 — restore data

  1. Restore Nextcloud from the DAS backup at /mnt/server-pc/Backups/Nextcloud/. Ensure nc-secrets.php has the original instanceid, passwordsalt, and secret values from the backup.
  2. Restore Pi-hole settings via Teleporter (Settings → Teleporter → Restore). The admin password is in /var/lib/pihole/secrets.env. Then recreate the split-horizon DNS overrides — see the SSL / external access section.
  3. Restore the Minecraft world from /mnt/server-pc/Backups/minecraft/ to /var/lib/minecraft/survival/.
  4. Trigger the music scanner: sudo systemctl start music-scanner
Pi-hole Teleporter After restoring via Teleporter, verify the admin port is still 8083 — Teleporter may reset FTLCONF_webserver_port back to 80. If the admin UI disappears, restart the container: sudo systemctl restart podman-pihole.service.
