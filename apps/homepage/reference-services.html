music-info-library

:5010 homeserver.lan:5010

Music metadata browser backed by a SQLite database of tracks scanned from the DAS. Flask / waitress.

source apps/music-info-library/ config modules/lan-apps.nix service music-info-library.service scanner music-scanner.service (oneshot) secrets /var/lib/music-info/secrets.env music path Set via MUSIC_PATH in the systemd unit in lan-apps.nix

Scanner

Reads Artist/Album/NN - Title.mp3 directory structure using 16 parallel CIFS workers. Scans ~27,000 tracks in ~13 minutes. Performs a full wipe and rebuild of the tracks table on every run.

sudo systemctl start music-scanner
journalctl -fu music-scanner          # live progress

Secrets

File: /var/lib/music-info/secrets.env (chmod 600, owned music-info:music-info)

DISCOGS_TOKEN=<discogs api token>
EMBY_API_KEY=<emby api key>
EMBY_BASE_URL=http://localhost:8096
EMBY_EXTERNAL_URL=https://intrentaka.com

Emby

:8096 / :8920 intrentaka.com

Media server running as a Podman container. Exposed externally via nginx reverse proxy with Let's Encrypt.

config modules/emby.nix service podman-emby.service image emby/embyserver (pinned digest) PUID / PGID 0 / 125 (sambashare gid) media /mnt/server-pc (CIFS) config dir /var/lib/emby/ LAN homeserver.lan:8096 external https://intrentaka.com

Groups and permissions

users.groups.sambashare.gid = 125 is shared by Emby (PGID=125), music-info, nextcloud, and kryt. Media files on the DAS are accessible to all services through this group. Do not change the GID.

Restart / upgrade

sudo systemctl restart podman-emby
journalctl -u podman-emby -f

To upgrade: update the pinned image digest in modules/emby.nix and rebuild.

Nextcloud

:443 cloud.intrentaka.com

Self-hosted cloud storage and collaboration. Native NixOS Nextcloud module (nextcloud34). MySQL backend. User data stored on the DAS over CIFS.

config modules/nextcloud.nix package unstablePkgs.nextcloud34 database MySQL (databases.nix) data dir /var/lib/nextcloud/data → CIFS //192.168.0.110/hsas01/Nextcloud/data admin URL https://cloud.intrentaka.com/login UID 991 (pinned via homeserver.nextcloudUid; drives both service user and CIFS uid=)

Secrets

FileOwnerModeContents
/var/lib/nextcloud-admin-passroot:root600Single-line admin password
/var/lib/nextcloud/nc-secrets.phpnextcloud:nextcloud400JSON with instanceid, passwordsalt, secret — must match backup or all user passwords break

Restore from backup

  1. Copy nc-secrets.php with original values from backup config.php.
  2. Restore the MySQL nextcloud database from backup.
  3. Restore the data directory from /mnt/server-pc/Backups/Nextcloud/.
  4. Run sudo -u nextcloud nextcloud-occ maintenance:repair if needed.
UID pin The Nextcloud service user UID (991) is declared once in modules/nextcloud.nix as homeserver.nextcloudUid. The CIFS data mount in hosts/homeserver/configuration.nix derives uid= from the same option. Never hardcode 991 in two places.

Pi-hole

:8083 homeserver.lan:8083/admin

Network-wide ad blocking and local DNS server. Running as a Podman container.

config modules/pihole-container.nix service podman-pihole.service image pihole/pihole:2026.07.2 (pinned) admin port 8083 (internal 8080 via FTLCONF_webserver_port=8080) DNS Port 53 UDP/TCP secrets /var/lib/pihole/secrets.env — WEBPASSWORD
Port pinning The internal web port is pinned to 8080 via FTLCONF_webserver_port=8080 in the container environment. If you restore settings via Teleporter without this env var present, Pi-hole will reset the internal port back to 80 and the admin UI will become unreachable on :8083. Always keep this env var in the container config.

Teleporter backup/restore

Settings → Teleporter → Download backup. Store the zip at /mnt/server-pc/Backups/pihole/.

To restore: Settings → Teleporter → Restore. After restoring, verify :8083/admin is still accessible. If not:

sudo systemctl restart podman-pihole
# Or: exec into the container and verify FTLCONF_webserver_port
sudo podman exec pihole env | grep FTLCONF

DNS router config

Set the router's primary DNS to 192.168.0.X (this machine's LAN IP) to route DNS through Pi-hole. Fallback DNS in Pi-hole: 1.1.1.1.

mc-control

:5020 homeserver.lan:5020

Web UI for managing the Minecraft server: start/stop, configure server.properties, and manage plugins. Flask / waitress, running as the mcctl system user.

source apps/mc-control/ config modules/minecraft.nix service mc-control.service state dir /var/lib/mc-control/ (settings.json, curseforge.env) user mcctl (system user, groups: mcctl mcplugins minecraft)

UI sections

SectionDescription
ConnectServer address with one-click copy to clipboard.
StatusRunning/stopped indicator with Stop/Start buttons. Shows uptime, players (names + count), world name, world type, game mode, and difficulty. World type / game mode / difficulty are always shown from the loaded config.
SettingsFull server.properties editor grouped by World, Gameplay, Players, Rendering, Performance, Resource Pack, and Server Info. Settings are persisted in /var/lib/mc-control/settings.json and applied to server.properties on every server start. The "Save & Restart" button saves then stops/starts the server.
PluginsSearch Modrinth or CurseForge (API key required), install from URL, list and delete installed plugins. Manages an allowed-hosts list that gates which download URLs are permitted.

Plugins

Plugin JARs are installed to /var/lib/minecraft/survival/plugins/. The mcctl user has write access via the minecraft group (mode 0770). New plugins take effect on the next server restart.

The allowed-hosts list is stored in /var/lib/mc-control/settings.json under the allowed_hosts key. When an install URL's hostname is not in the list, a prompt appears offering to add it.

Default allowed hosts: cdn.modrinth.com, hangar.papermc.io, github.com, objects.githubusercontent.com, mediafilez.forgecdn.net, edge.forgecdn.net.

CurseForge API key

Create a key at console.curseforge.com. Store it as:

sudo tee /var/lib/mc-control/curseforge.env <<'EOF'
CURSEFORGE_API_KEY=<your key>
EOF
sudo chown mcctl:mcctl /var/lib/mc-control/curseforge.env
sudo chmod 600 /var/lib/mc-control/curseforge.env
Shell quoting Use a heredoc with a single-quoted delimiter (<<'EOF') when writing the key. CurseForge keys are bcrypt hashes containing $ characters that the shell will try to expand if you use double quotes.

CurseForge version matching

The resolver tries (in order): exact version match in latestFilesIndexes, exact match in latestFiles[].gameVersions, family match (e.g. "1.19" for a 1.19.4 server), family match in latestFiles. If none found it returns an error with the available MC versions rather than silently installing the wrong version.

The /v1/mods/{id}/files endpoint returns 403 on the free API tier — the resolver works entirely from the data in /v1/mods/{id}.

sudo wrapper mc-control calls /run/wrappers/bin/sudo (the setuid wrapper NixOS creates at boot), not /run/current-system/sw/bin/sudo which lacks the setuid bit. If mc-control returns {"status":"unknown"} after a rebuild, verify the wrapper exists and is setuid root: 
ls -la /run/wrappers/bin/sudo

Minecraft

:25565 LAN only

Paper 1.19.4 server. Does not start at boot — managed via mc-control or systemctl. LAN-only (online-mode=false; Mojang account not required).

config modules/minecraft.nix service minecraft-server-survival.service package pkgs.paperServers.paper-1_19_4 data dir /var/lib/minecraft/survival/ plugins dir /var/lib/minecraft/survival/plugins/ (mode 0775, group mcplugins) autoStart false online-mode false (LAN only — do not expose port 25565 externally without enabling this) JVM opts -Xms1G -Xmx3G

Start / stop

# Via mc-control web UI (preferred)
http://homeserver.lan:5020

# Via systemctl
sudo systemctl start  minecraft-server-survival
sudo systemctl stop   minecraft-server-survival
sudo systemctl status minecraft-server-survival
journalctl -u minecraft-server-survival -f

Plugins

Plugins are managed from the mc-control Plugins section. JARs go in /var/lib/minecraft/survival/plugins/. The mcctl user (mc-control's service account) can write there via the minecraft group.

Plugins only load on server startup — install or delete while the server is stopped, then start it.

nix-minecraft tmpfiles note The survival/ directory is created and owned by minecraft:minecraft (0770) by the nix-minecraft activation script, which runs after systemd tmpfiles. A tmpfiles rule setting survival/ to mode 0771 is overwritten on each rebuild. The current solution is adding mcctl to the minecraft group, giving it group-level rwx without needing to change directory permissions.

World backup

The mc-backup systemd timer runs daily at 03:00 and rsyncs the world to the DAS. If the machine was off at 03:00, it runs on next boot (Persistent=true).

source /var/lib/minecraft/survival/ destination /mnt/server-pc/Backups/minecraft/YYYY-MM-DD/ retention 7 most recent daily backups skip condition Silently skips if /mnt/server-pc is not mounted 
systemctl list-timers mc-backup      # next run time
journalctl -u mc-backup              # last run result

Pinned settings (NixOS-managed)

These two properties are set in modules/minecraft.nix and are not editable from mc-control:

server-port 25565 online-mode false
